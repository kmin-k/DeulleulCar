# 들를Car UX 설계 (T2)

## 0. 설계 원칙
1. **말 한 번, 확인 한 번.** 볼일 입력은 발화 1회, 계획 확정은 "응" 1회로 끝낸다.
2. **차의 할 일은 제안만 한다.** 긴급 등급이어도 사용자 허락 없이는 경로를 바꾸지 않는다. 대신 등급이 높을수록 더 강하게, 더 자주 알린다.
3. **주행 중에는 보는 UI가 아니라 듣는 UI.** 주행 중 화면에는 글자 3줄 이하만 두고, 터치 대상은 큰 버튼 최대 2개로 제한한다. 세부 정보는 정차했을 때만 보여 준다.
4. **말 걸 타이밍을 고른다.** 다음 회전 지점이 가까우면(TBT 300m 이내) 음성 제안을 미룬다. 한 번 주행하는 동안 같은 할 일은 최대 1번만 제안한다.
5. **잊히지 않게.** 미룬 할 일은 사라지지 않는다. 주행 중 카드에 배지로 남기고, 시동을 걸 때와 도착했을 때 한 줄로 요약해 준다.

## 1. 상태 모델
| 차량 상태 | 판정 근거 (구현 시 확정) | 화면 |
|---|---|---|
| 정차 (PARKED) | 속도 0 + 정차 지속, 또는 AAOS 주행 제한(UX Restrictions) 해제 | 홈 / 계획 확인 / 할 일 상세 / 설정 |
| 주행 (DRIVING) | 속도 > 0, 또는 주행 제한 활성 | 주행 미니 카드 / 긴급 알림 |

## 2. 차의 할 일 등급과 알림 강도
| 등급 | 예시 (Vehicle SDK) | 감지 즉시 | 경로를 짤 때 | 주행 중 기회 | 미루면 |
|---|---|---|---|---|---|
| 🔴 긴급 | 브레이크액 부족, 주행 가능 거리 30km 미만 | TTS로 즉시 알림 + 긴급 카드 | 첫 정류지로 강하게 추천 | 해결지가 근처에 있으면 재안내 | 10분 뒤 다시 알림. 끌 수 없음 |
| 🟠 권장 | 타이어 저압(TPMS 경고등), 주행 가능 거리 80km 미만, 엔진오일 레벨 | 정차 중이면 TTS 한 줄, 주행 중이면 배지만 | "겸사겸사 넣을까요? +N분" 추천 카드 | 우회 ≤ 5분인 해결지가 있으면 1회 제안 | 거절 3회 또는 3일이 지나면 문구를 한 단계 강하게 |
| ⚪ 보류 | 워셔액 부족, 정기 점검 시점 | 배지만 | 우회 ≤ 3분일 때만 추천 | 제안하지 않음 | 목록에 유지하고, 시동·도착 때 요약 |

## 3. 화면 목록
| ID | 화면 | 상태 | 핵심 요소 |
|---|---|---|---|
| S1 | 홈 | 정차 | 좌측: 사람의 할 일(오늘 들를 곳) + 큰 마이크 버튼. 우측: 차의 할 일 카드(등급 배지, 한 줄 설명, 가장 빠른 해결지 +N분) |
| S2 | 계획 확인 | 정차 | 순서 리스트(번호, 장소, 도착 예정, 영업 종료, 누적 +N분). 추천된 차의 할 일은 점선 카드 [넣기][다음에]. 하단 [출발] |
| S3 | 주행 미니 카드 | 주행 | 다음 정류지, 남은 정류지 수, 차의 할 일 배지, 마이크 버튼 1개 |
| S4 | 긴급 알림 | 주행·정차 | 빨간 전면 카드, 3줄 설명, [가까운 곳 들르기][나중에] |
| S5 | 할 일 상세 | 정차 | 이게 무슨 뜻인지 / 지금 위험한지 / 계속 달려도 되는지 / 해결 방법·예상 시간 / 해결 장소 후보 |
| S6 | 설정 | 정차 | 집·회사 위치, API 키(선택), 데모 모드 |

## 4. 시나리오와 음성 스크립트

### 시나리오 1 — 퇴근길 볼일 (사람의 할 일)
- **상황**: 평일 18:40, 회사 주차장. 정차 상태.
- **흐름**: S1 마이크 → 발화 → S2 → "응" → 출발 → S3

| 화자 | 대사 / 동작 |
|---|---|
| 사용자 | "퇴근길에 약국이랑 마트 들렀다 집에 가자" |
| 앱 (처리) | 볼일 2개 + 목적지(집) 추출 → 경로 근처 후보 검색 → 영업시간 확인 → 순서 결정 |
| 앱 (TTS) | "약국이 7시에 닫아서 먼저 갈게요. 약국, 마트 순서로 들르면 평소보다 9분 더 걸려요. 출발할까요?" |
| 사용자 | "응" |
| 앱 | NaviHelper로 경유지 2개 + 목적지 세팅 → S3 |

### 시나리오 2 — 정류지 3개 이상 (롤링 경유지)
- **발화**: "세탁소, 약국, 마트 들렀다 집"
- **동작**: 내비에는 [세탁소, 약국]만 경유지로 넣는다. 세탁소 도착(`onWayPointArrived`) → 마트를 SECOND 슬롯에 추가.
- **TTS (도착 시)**: "세탁소 도착했어요. 다음은 약국, 그다음 마트예요."
- **사용자 체감**: 정류지가 몇 개든 한 번 말하면 끝. 내비의 2개 제한은 사용자에게 보이지 않는다.

### 시나리오 3 — 타이어 저압 (차의 할 일, 권장)
- **트리거**: 아침 출근길 주행 중 좌측 앞 타이어 저압 감지 (Virtual Console로 재현)
- **주행 중**: TTS를 하지 않는다. S3에 🟠 배지 1개만 추가 (회전 직전이라 말을 미룸).
- **회사 도착 후 정차**: TTS "왼쪽 앞 타이어 공기압이 낮아요. 당장 위험하진 않지만 오늘 안에 채우는 게 좋아요. 퇴근길 경로에 넣어 둘까요?" → "나중에"
- **퇴근 때 시나리오 1을 발화하면**: S2에 추천 카드 "OO주유소 공기주입기, 경로상 +3분. 들를까요?" → "응" → 순서를 다시 계산해 약국 → 주유소 → 마트로 편성
- **핵심 메시지**: 차가 경로에 마음대로 끼워 넣지 않는다. 하지만 사용자가 경로를 짤 때 가장 좋은 타이밍에 다시 꺼내 준다.

### 시나리오 4 — 연료 극저 (차의 할 일, 긴급)
- **트리거**: 주행 가능 거리 25km
- **TTS (즉시)**: "연료가 25km 정도 남았어요. 경로상 2km 앞 OO주유소가 리터당 1,689원으로 가장 가까워요. 들를까요?"
- **S4**: [들르기][나중에]. "나중에"를 고르면 10분 뒤 또는 다음 정차 때 다시 알림.

### 도착·시동 요약
- **도착 (`onDestinationArrived`)**: "도착했어요. 차의 할 일이 1개 남아 있어요: 워셔액 보충."
- **시동 (앱 시작)**: 보류·권장 항목이 있을 때만 한 줄로 요약.

## 5. 문구 규칙
- 경고 설명은 항상 같은 3단 구조: **무엇** ("왼쪽 앞 타이어 공기압이 낮아요") → **지금 위험한가** ("당장 위험하진 않지만") → **언제까지** ("오늘 안에")
- 숫자는 반올림해서 말한다 ("+3분", "25km 정도").
- 질문은 항상 "들를까요?"로 끝낸다. 답은 예/아니오만 받는다 (브랜드 일관성).
- 확신할 수 없는 정보(영업시간 기본값 등)는 "보통 ~시까지예요"처럼 단정하지 않는다.
